# Authentication

V1 sign-in authenticates an account and returns a `JWT` cookie. The token can be sent as a bearer token to authenticated v2 endpoints, including `GET /v2/me`.

## Sign in

<ApiEndpoint
  method="POST"
  path="/auth/signin"
  summary="Sign in and receive a JWT session cookie."
/>

### Request

#### Headers

| Name            | Type                                       | Value              |
| --------------- | ------------------------------------------ | ------------------ |
| `Authorization` | <ApiBadge kind="auth" label="string" />    | `JWT`              |
| `Content-Type`  | <ApiBadge kind="neutral" label="string" /> | `application/json` |

#### Body

```json
{
  "email": "<email>",
  "password": "<password>",
  "device_id": "<device-id>"
}
```

#### Body Fields

| Field       | Type                                       | Description                                            |
| ----------- | ------------------------------------------ | ------------------------------------------------------ |
| `email`     | <ApiBadge kind="neutral" label="string" /> | Account email address.                                 |
| `password`  | <ApiBadge kind="neutral" label="string" /> | Account password.                                      |
| `device_id` | <ApiBadge kind="neutral" label="string" /> | Client device identifier. Requiredness is unspecified. |

#### Example

```http
POST /v1/auth/signin
Authorization: JWT
Content-Type: application/json

{"email":"<email>","password":"<password>","device_id":"<device-id>"}
```

Browser `fetch` does not expose the `Set-Cookie` response header to JavaScript. Use a server-side client to read the token from this header.

### Response

The successful response includes a `Set-Cookie` header containing the `JWT` session token and a JSON body with `payload.user`:

```json
{
  "payload": {
    "user": {
      "id": "<user-id>",
      "slug": "<user-name>",
      "platform": "<string>",
      "region": "<string>",
      "locale": "<string>",
      "role": "<string>",
      "reputation": 0,
      "unread_messages": 0,
      "check_code": "<string>",
      "banned": false,
      "verification": false,
      "anonymous": false,
      "linked_accounts": {
        "steam_profile": false,
        "patreon_profile": false,
        "xbox_profile": false,
        "discord_profile": false,
        "github_profile": false
      },
      "ingame_name": "<string>",
      "avatar": null,
      "background": null,
      "has_mail": false,
      "crossplay": false,
      "written_reviews": 0
    }
  }
}
```

The response also sets a `JWT` cookie. Token expiry and an error response schema are unspecified.

| `payload.user.region`          | <ApiBadge kind="neutral" label="string" />         | Region.                            |

| `payload.user.role`            | <ApiBadge kind="neutral" label="string" />         | Account role.                      |

## Use the token with v2

Send the extracted token as a bearer token on authenticated requests:

```http
Authorization: Bearer <token>
Content-Type: application/json
```

The v1-issued bearer token is accepted by authenticated v2 endpoints. Other authenticated v2 operations may have operation-specific requirements.

## Sign out

<ApiEndpoint method="GET" path="/auth/signout" summary="End the current v1 session." />

Send the session token as the `JWT` cookie. The request has no body.

### Request

```js
const response = await fetch('https://api.warframe.market/v1/auth/signout', {
  method: 'GET',
  headers: {
    Accept: 'application/json',
    Cookie: `JWT=${token}`,
    'Content-Type': 'application/json',
    Language: 'en',
    Platform: 'pc',
  },
});
```

### Response

The endpoint returns HTTP `200`, a JSON `payload.user`, and a replacement `JWT` cookie representing an anonymous session. The replacement token is not accepted by v2 `GET /v2/me`.

The original sign-in token may remain accepted by v2 `GET /v2/me` after sign-out. Sign-out replaces the browser cookie but does not guarantee revocation of a previously issued bearer token for v2.
