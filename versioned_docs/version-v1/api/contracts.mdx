# Contracts

These endpoint specifications use the v1 base URL `https://api.warframe.market/v1`. Examples use placeholders for account data, message content, and identifiers.

Authentication routes are documented on [Authentication](./authentication). Statistics routes are documented on [Statistics](./statistics).

## Messaging

### Get chats

<ApiEndpoint
  method="GET"
  path="/im/chats"
  summary="Get chats belonging to the current account."
  badges={[{ kind: 'auth', icon: '🔒', label: 'Auth required' }]}
/>

<ApiCallout kind="warning" icon="🔒" title="Requires">

- A signed-in session sent with the `JWT` cookie.

</ApiCallout>

### Request

#### Query Parameters

| Name      | Type                                       | Description                                     |
| --------- | ------------------------------------------ | ----------------------------------------------- |
| `include` | <ApiBadge kind="neutral" label="string" /> | Optional. Use `chats` to include chat messages. |

#### Headers

| Name       | Type                                       | Example       |
| ---------- | ------------------------------------------ | ------------- |
| `Cookie`   | <ApiBadge kind="auth" label="string" />    | `JWT=<token>` |
| `Language` | <ApiBadge kind="i18n" label="string" />    | `en`          |
| `Platform` | <ApiBadge kind="neutral" label="string" /> | `pc`          |

### Response

#### Body

Without `include`, the response contains chat summaries. `messages` may be empty.

```json
{
  "payload": {
    "chats": [
      {
        "id": "<chat-id>",
        "chat_name": "<string>",
        "last_update": "<date-time>",
        "unread_count": 0,
        "chat_with": [
          {
            "id": "<user-id>",
            "slug": "<user-name>",
            "ingame_name": "<string>",
            "platform": "pc",
            "region": "<string>",
            "locale": "en",
            "status": "<string>",
            "last_seen": "<date-time>",
            "reputation": 0,
            "crossplay": false,
            "avatar": null
          }
        ],
        "messages": []
      }
    ]
  }
}
```

#### Data Fields

| Field                     | Type                                               | Description                               |
| ------------------------- | -------------------------------------------------- | ----------------------------------------- |
| `payload.chats`           | <ApiBadge kind="neutral" label="Chat[]" />         | Chats for the signed-in account.          |
| `chats[].id`              | <ApiBadge kind="neutral" label="string" />         | Chat identifier.                          |
| `chats[].chat_name`       | <ApiBadge kind="neutral" label="string" />         | Chat display name.                        |
| `chats[].last_update`     | <ApiBadge kind="neutral" label="string" />         | Timestamp of the latest chat activity.    |
| `chats[].unread_count`    | <ApiBadge kind="neutral" label="number" />         | Number of unread messages.                |
| `chats[].chat_with`       | <ApiBadge kind="neutral" label="User[]" />         | Chat participants.                        |
| `chats[].messages`        | <ApiBadge kind="neutral" label="Message[]" />      | Messages included for the chat.           |
| `chat_with[].id`          | <ApiBadge kind="neutral" label="string" />         | Participant identifier.                   |
| `chat_with[].slug`        | <ApiBadge kind="neutral" label="string" />         | Participant URL name.                     |
| `chat_with[].ingame_name` | <ApiBadge kind="neutral" label="string" />         | Participant in-game name.                 |
| `chat_with[].platform`    | <ApiBadge kind="neutral" label="string" />         | Participant platform.                     |
| `chat_with[].region`      | <ApiBadge kind="neutral" label="string" />         | Participant region.                       |
| `chat_with[].locale`      | <ApiBadge kind="neutral" label="string" />         | Participant locale.                       |
| `chat_with[].status`      | <ApiBadge kind="neutral" label="string" />         | Participant status.                       |
| `chat_with[].last_seen`   | <ApiBadge kind="neutral" label="string" />         | Participant last-seen timestamp.          |
| `chat_with[].reputation`  | <ApiBadge kind="neutral" label="number" />         | Participant reputation.                   |
| `chat_with[].crossplay`   | <ApiBadge kind="neutral" label="bool" />           | Whether participant crossplay is enabled. |
| `chat_with[].avatar`      | <ApiBadge kind="neutral" label="string or null" /> | Participant avatar URL, when present.     |

### Get chats with messages

`GET /im/chats` accepts `include=chats`. In addition to `payload.chats`, the response includes an `include` object with the included chats and unread-message count.

#### Request

```http
GET /v1/im/chats?include=chats
Cookie: JWT=<token>
Accept: application/json
Language: en
Platform: pc
```

#### Response

```json
{
  "payload": {
    "chats": [
      {
        "id": "<chat-id>",
        "chat_name": "<string>",
        "last_update": "<date-time>",
        "unread_count": 0,
        "chat_with": [],
        "messages": [
          {
            "id": "<message-id>",
            "chat_id": "<chat-id>",
            "message_from": "<user-id>",
            "send_date": "<date-time>",
            "message": "<message text>",
            "raw_message": "<raw message text>"
          }
        ]
      }
    ]
  },
  "include": {
    "chats": [],
    "unread_messages": 0
  }
}
```

The `include.chats` entries have the same shape as `payload.chats`. Message text is user-generated content.

Chat messages can contain private, user-generated content. Do not publish message values in examples or logs.
